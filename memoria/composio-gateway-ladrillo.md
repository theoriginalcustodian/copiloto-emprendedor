**`ComposioGateway`** — el boundary de seguridad **fail-closed** entre un agente (LLM no confiable) y los servicios externos vía Composio. **Tercer provider agnóstico** del arquetipo `conversational_agent` (gemelo de `LlmProvider`/`GroqSTT`). **Reusalo tal cual en cualquier app con Composio — no reinventes el boundary** (una omisión = lethal trifecta). Construido a mano (gate senior, no la fábrica: es capa plantilla + el gate Docker `--network none` no puede validar la integración real). **PR #95 → main** (`c9541cb`), 2026-06-30.

**Dónde:** `deploy/skeleton_kit/archetypes/conversational_agent/reference/clients/agent/providers/composio_gateway.py`. Spec/plan: `docs/superpowers/{specs,plans}/2026-06-30-composio-gateway*`. Dep: `composio==0.17.1` (pinned).

**Contrato:** `ComposioGateway(policy)` donde `policy = {toolkit: ToolkitPolicy(version, read={slugs}, write={slugs})}`. La policy es **por-dominio** (qué permite el agente); el `user_id` (tenant) va **por-call**. Lo construye el `context_factory` del dominio. Dos planos: **ejecución** (`execute(slug, *, user_id, arguments, confirmed=False)` + `allowed_tools(toolkit, mode)`) + **conexión** (`authorize`/`list_connections`/`connection_status`/`revoke`).

**Fail-closed en profundidad** (lo que lo hace "imposible de usar mal"): (1) sin policy no se construye; (2) denylist de meta-tools (`COMPOSIO_REMOTE_BASH_TOOL`/`MULTI_EXECUTE`) **gana sobre la policy**; (3) slug fuera de `read∪write` → `ToolNotAllowed`; (4) write sin `confirmed=True` → `ConfirmationRequired` → **doble candado** con el HITL del dispatcher contra una alucinación del LLM. Token OAuth nunca toca el código/payload (brokering de Composio).

**Lecciones de territorio (plano de EJECUCIÓN):** versión **pineada por-toolkit** (el SDK rechaza `"latest"`) **Y la version DEBE existir en `client.toolkits.get(tk).meta.available_versions`** — una inventada NO falla el de-risk del slug pero da **404 `Tool_ToolNotFound` al EJECUTAR** (rompió el 1er E2E de B: `20260626_00` no existía; gcal real = `20260623_00`). Validá la version contra el catálogo, no solo el slug (test `test_version_pineada_existe_real`). ⚠️ **la version GMAIL del #95 (`20260626_00`) es placeholder SIN validar — corregir antes del E2E de Gmail (Fase 1).** · `CREATE_EVENT` necesita `start_datetime`+`end_datetime` **naive-local** + `timezone` IANA (solo `event_duration_minutes` → `successful:False`); mandar UTC con offset corre +3h en el display · **SDK key ≠ MCP key** (la MCP da 401 en el SDK) · loader de test `importlib` necesita `sys.modules[name]=mod` antes de `exec_module` (py3.14 `@dataclass`) · SDK lazy en el `client_factory` default → unit (mock) corren sin composio.

**🔴 2º uso real (Calendar, PR #97) — 4 bugs del plano de CONEXIÓN que los unit con fake (toolkit=string) NO cazaron** (por qué importan: el fake mockeaba un contrato distinto al real → "verde" mentía): (1) `connection_status` comparaba el **objeto `ItemToolkit` vs slug string** → `None` aun con conexión `ACTIVE`; fix `_slug_of`+case-insensitive. (2) `authorize()` usaba el endpoint legacy `sdk.create().authorize()`, **retirado por Composio (400 `ConnectedAccount_BadRequest`)** → fix `connected_accounts.link(user_id, auth_config_id)` + `auth_configs.list(toolkit_slug=)`. (3) `list_connections`/`_auth_config_id` caían al objeto contenedor con `items==[]` (usuario sin conexiones) → `TypeError`; fix `_unwrap_items` (distingue 'sin attr' de 'lista vacía'). (4) read-back E2E: `json.dumps(ensure_ascii=True)` **escapaba el acento** de «Reunión» → substring nunca matcheaba; comparar summaries extraídos, no dump. Cada uno con regresión en `test_composio_gateway.py` (capa plantilla). **Moraleja: un fake que no reproduce la FORMA real del SDK (objeto vs string, endpoint vigente) da falsos verdes — el integration real contra Composio es indispensable.**
