**Spike S3 (2026-06-29) — VALIDADO E2E.** El agente de voz en vivo full-duplex (Canal C del spec `2026-06-29-clinic-agenda-agent-design.md`, Fase 3) **funciona** desde el móvil: browser (getUserMedia) → WebSocket → FastAPI en el VPS → Voxtral STT realtime → GPT-4o mini → Voxtral TTS → browser. Probado en vivo vía túnel cloudflared HTTPS. Evidencia: `spikes/clinic-agent-s3-voice-ws/RESULT.md` (8 probes + prueba hands-on).

**Stack decidido (todo medido, no asumido):**
- **STT realtime = Voxtral** `voxtral-mini-transcribe-realtime-2602` — es-AR perfecto, finalización **223ms**.
- **Cerebro = GPT-4o mini DIRECTO a OpenAI** (NO OpenRouter — el routing metía jitter de 1.1–5.7s con DeepSeek). TTFT mediana ~1s. Groq llama-3.3-70b ~150ms queda como alternativa de latencia (puerto A-1). El `LlmProvider` swappable → voz usa GPT-4o mini, texto sigue DeepSeek.
- **TTS = Voxtral** `voxtral-mini-tts-2603` — first-byte streaming 613ms.
- **Boundary realtime↔Temporal viable:** signal 5.6ms / query 13.9ms al Temporal local (<<50ms) → la voz al borde llama al core durable como tools; Temporal fuera del hot-path (confirma el invariante §3 del spec).

**Hallazgos "no codificar la esperanza" (todos pillados por probar contra realidad):**
- `mistralai 2.5.0` es namespace package: entry point real = `from mistralai.client import Mistral`; tipos realtime en `mistralai.extra.realtime`. La guía Voxtral está 2 generaciones atrás.
- El `response_format="pcm"` de Voxtral TTS es **float32 LE @ 24kHz**, NO int16 (leerlo como int16 = ruido de interferencia total). Verificado vs el header WAV.
- El TTS sale bajo (peak 0.30, rms 0.037 ≈ −28dB). ⚠️ **CORREGIDO 2026-06-30:** normalizar/comprimir en el server lo vuelve **robótico** ("locutor de radio") → REVERTIDO, se manda **PCM crudo** de Voxtral (ver bloque Fase 3.1). El crudo suena natural pese al volumen bajo; el volumen se compensa client-side si hace falta.
- Las 10 voces preset de TTS son **inglesas** (no hay es-AR) → para producción clonar/crear voz (`voices.create(languages=["es"])` / `ref_audio`).
- `ScriptProcessorNode` corre en el main thread → glitchea el audio si el browser renderiza → en prod usar **AudioWorklet**.

**Backlog de Fase 3 (lo que el prototipo reveló que falta para NATURALIDAD — no son fallas de viabilidad):** streaming-por-oración (LLM+TTS, mata la pausa fin-habla→respuesta) · barge-in (poder interrumpir) · AudioWorklet (jank) · voz es-AR · normalización de volumen en server · turn-detection (Voxtral NO lo hace — es 100% cliente). **Roadmap dedicado e independiente** (no en el ROADMAP maestro, por decisión del operador 2026-06-29) → `docs/Follow up/2026-06-29-agente-voz-realtime-roadmap.md` (fases 3.0 de-risk → 3.4 hardening, cada una con gate). El **failure-map de 25 modos** (research SOTA, checklist de impl) → versionado en `docs/research/2026-06-29-voice-agent-sota-failuremap.md`.

**Superficie de config REAL de Voxtral (introspección SDK 2.5.0, 2026-06-29):** casi cero perillas. STT realtime: solo `audio_format` + `target_streaming_delay_ms` (480 validado); **NO hay VAD/turn-detection de servidor** → turn-taking 100% nuestro. TTS: solo `voice_id`/`ref_audio`/`response_format`/`stream`; **NO hay velocidad/prosodia/pitch/volumen** → normalizar PCM en server. Voz es-AR solo vía `voices.create(languages=["es"])`/`ref_audio` (las 10 preset son inglesas). ⇒ de los 4 síntomas del prototipo, solo la voz "rara" es lever de Voxtral; trabado/pausa/volumen = arquitectura nuestra (Fase 3).

Fix en el **SYS** (única capa con control) → **SYS v3**: español blindado (anti-EN) + concordancia horas (la una / las once, nunca "a la 11") + teléfonos dígito-por-dígito + naturalidad (2 oraciones, números en palabras, eco(.)+pregunta corta, disfluencias).
