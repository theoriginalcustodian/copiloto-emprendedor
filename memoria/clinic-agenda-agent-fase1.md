**Qué es:** agente conversacional durable sobre Temporal — el paciente escribe por **Telegram texto** y agenda/consulta turnos en lenguaje natural. Motor `ConversationWorkflow` **100% agnóstico** (loop durable recibir(signal)→call_llm→dispatch_intent→responder/HITL; determinismo regla 3) + capa dominio clínica (`clinic_conversation.py`: system prompt + dispatcher máquina de estados + context). **Closed-list**: nunca inventa profesional/slot/paciente (todo contra fusion). (2) **`workflow_id` único por run** — `USE_EXISTING` enruta el signal a un workflow abandonado del run previo. (3) sync drift PC↔VPS. **Fase 1.5 ✅ (2026-06-29, clinic-management PR #5 + kit PR #92):** confirmación por **botón** (inline keyboard) + robustez de texto. **Bug cazado en prueba EN VIVO** (lo que el gate con LLM scripted no podía cazar): el confirm dependía de que Flash emitiera `action=confirm_pending` exacto, y Flash en inputs coloquiales **rompe el JSON** ("si dale" → texto plano → parsed=null → "no te entendí") o devuelve **otra action** ("book") — aunque entienda. Causa raíz: el dispatcher priorizaba la `action` del LLM sobre el ESTADO (`collecting=confirm`); el fallback `_infer_confirmation` existía pero era inalcanzable. Fix: **botón determinístico** (`DispatchResult.choices` → motor agnóstico → canal renderiza; tap → `kind=callback` → intent sin LLM) **+ bypass `collecting=confirm`** (estado manda sobre action; unifica botón+texto). **Lección sistémica:** una decisión discreta (confirmar/elegir) NO debe ir por NLU — botón primario + texto robusto como fallback. El gate scripted prueba la orquestación pero NO la (in)fiabilidad del LLM real → validar comportamiento del LLM real en vivo. Gate E2E ampliado a 4 escenarios (botón + "si dale" robusto). [[no-codificar-la-esperanza-principio-raiz]]

**Fase 1.6 ✅ (2026-06-29):** disponibilidad **natural + humanizada**. Bug en vivo: pidiendo "el martes a la tarde" insistía con 09:00 (mañana) y tras cancelar repetía el mismo turno; seco. Causa raíz: `_parse_time("a la tarde")`=None (el regex exige dígito) → franja descartada → `slots[0]`; + proponía 1 solo slot sin alternativas (cancel = dead-end). Fix: `resolve_datetime` devuelve `period` (morning/afternoon/evening) cuando hay franja sin hora; el dispatcher **filtra a la franja y ofrece una LISTA de horarios como botones** (3-4 + ver más + otro día), **tocar uno = agenda directo** (sin confirm extra). Sin lugar → lo dice + ofrece otros horarios/próximos días (cancel ya no es dead-end). **Tono humanizado** (system prompt sección "cómo hablás" + replies del dispatcher: cálido/cercano/rioplatense + emojis ocasionales). **Lección:** ofrecer opciones > imponer una; resolver preferencias blandas (franja); el tono vive en prompt + dispatcher, no solo en el LLM; el gate scripted NO valida tono ni LLM real → probar en vivo. Gate E2E = 5 escenarios (franja→lista→tap). [[costo-incertidumbre-precision-ratchet]]
